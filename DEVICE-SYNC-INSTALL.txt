AssetGuard — Device details reflect the CONFIRMED command (on refresh)
======================================================================

You confirmed: motion / moving interval / wake-up ARE queued and DO reach
"confirmed" in the command queue, but the live value in Device details never
flips. The broken link was the confirmed-command -> live-value promotion.

FIX (this is the only change):
  reconcileDevicePending now sets the LIVE value straight from the CONFIRMED
  command in the queue, not from the pending marker. On each device read, for
  motion / moving interval / wake:
    - a command still in flight (pending/sent/acked) -> leave it ("-> pending").
    - the newest CONFIRMED command -> set the live value to that command's number
      (e.g. GS,40 -> motion 40; update,10 -> interval 10s; UPT,720 -> wake 12h)
      and clear the pending marker.
    - nothing confirmed/active but a stale marker -> drop the marker.
  So when a command shows "confirmed", REFRESH the device page and the value
  (and the slider baseline) now shows it. Independent of the pending marker and
  of whether the ingest's own promotion fired.

(No auto-refresh — it updates on the next load of the page, as you asked.)
